# 平台总体架构与分期规划

> 本文档基于前端原型（web/）功能核查与 dobot_quad_sdk 能力核查结果编写。
> 前端功能 × SDK 兼容明细见 [sdk-compatibility.md](sdk-compatibility.md)。

## 0. 前置结论

- **机型/SDK**：DOBOT Rover X1 Explorer 轮足机器狗，官方 SDK `dobot_quad_sdk`（MIT，Python + C++），三层接口：高层 gRPC（`192.168.5.2:50051`，WiFi/有线均可）+ 低层 CycloneDDS（**仅有线** `192.168.5.0/24`）+ RTSP 视频（`:8554`）。
- **前端现状**：`web/` 为纯 UI 原型 + 本地 mock，无任何真实网络通信代码；`server/`、`robot-agent/` 仅有 README，实现为空。
- **SDK 不支撑**：SLAM/建图/导航/全局定位、热成像、激光雷达、OTA/重启/标定等设备管理接口——见 §5 缺口与对策。

### 终端分层定位

| 终端 | 面向角色 | 管控方向 | 典型功能 |
| --- | --- | --- | --- |
| Web 管控台 | 管理者/监控中心 | "面"：集群与业务 | 多机状态、任务排期、告警闭环、报表、权限、OTA |
| 安卓平板 App | 现场操作员 | "点"：单机与实时 | 绑机、FPV 遥控、姿态动作、接管/急停、喊话 |

管控差异三条：**空间维度**（一群狗 vs 一条狗）、**延迟容忍**（云端中继数百 ms vs 局域网直连 <200ms）、**操作性质**（异步计划 vs 同步实时操控）。

SDK 高/低层与终端分层同源：高层 gRPC 是"用户语言"（语义化动作，WiFi 可用，有状态机兜底），同时服务 Web 与平板；低层 DDS 是"工程语言"（原始量 + `kill_robot` 等高危操作），只被 robot-agent 消化，**永不暴露给任何终端**。

## 2. 四条核心数据通路

| 通路 | 链路 | 说明 |
| --- | --- | --- |
| 遥测上行 | DDS/gRPC → agent 聚合为高层语义 → MQTT → server → WS → Web/平板 | agent 把 `LowerState` 翻译成电量%/RPY/温度，终端不感知 DDS |
| 指令下行 | Web/平板 → REST/WS → MQTT（带指令 ID）→ agent → gRPC → 逐级回执 | 急停走最高优先级队列 |
| 视频 | RTSP:8554 → agent 拉流 → 流媒体网关 → WebRTC 到终端；分一路给 AI 推理 | 平板 LAN 模式直连 RTSP，延迟最低 |
| 平板直连 | 平板 →(局域网)→ agent 本地服务 → gRPC/RTSP | 现场遥控不绕云端；云端模式仅用于远程查看 |

## 3. 关键架构决策

1. **robot-agent 必须跑在狗载上位机上**。DDS 低层接口仅有线可达，而语音喊话、电机温度、BMS、IMU 均挂在 DDS 上；agent 机内直连 DDS，对外只暴露 MQTT。此决策决定端侧硬件形态（需随狗上位机，如 Jetson/工控机）。
2. **高低层隔离**：SDK 低层（电机直控、`kill_robot`）只在 agent 内部使用；云端与平板可调用的能力上限 = SDK 高层 gRPC 集合 + agent 聚合遥测。
3. **安全链路独立于业务链路**：agent 本地心跳看门狗，断链超时自动 `ready()`/`passive()`，不依赖云端可达；"人工接管"= 控制信道所有权（云端 vs 平板直连）互斥切换，在 agent 上实现"控制权锁"。
4. **导航能力独立成柱**：不阻塞主链路，作为独立 R&D 线（见 §5、P3）。

## 4. 分期规划

### P0 — 打通单机遥控闭环（一条狗、一个网页、真控真看）

落地前端已验证与 SDK 兼容的遥控功能（兼容清单 §一）：

- **robot-agent**：gRPC 封装（`velocity_sequence` 方向遥控、姿态状态机、LED、急停）、DDS 遥测采集、MQTT 客户端、RTSP 转发。
- **server**：MQTT 网关、WebSocket 推送、JWT 鉴权（替换 `web/src/stores/auth.ts:99` 的 mock 登录）。
- **web**：监控页接线（九宫格/速度/姿态/LED/急停/遥测/视频 WebRTC），补齐未绑定按钮的事件。
- **验收**：Web 遥控真狗行走/转向/站趴/变色，视频 <500ms，遥测 1Hz 刷新。

### P1 — 业务闭环（巡检平台可用）

- **server**：告警中心、任务管理（先做**手动触发**型任务，回避导航缺口）、设备档案、报表导出、RBAC。
- **ai/**：视频帧 → 烟火/越界/过温等检测 → 告警事件 → MinIO 抓图存档。
- **web**：任务/告警/设备/报告/系统五页接真接口；修正设备页不实参数（电机 x/12→x/16，删除 D435i/BMI088/MID-360 虚标）。
- **验收**：手动下发任务 → 人工遥控巡检 → AI 出告警 → 处置闭环 → 出报告，全流程跑通。

### P2 — 安卓平板端（现场单机操控）

- 功能：单机遥控 + FPV、姿态/动作面板（补 SDK 的避障开关、动作库、平衡微调，见兼容清单 §三）、语音喊话/监听、**接管/急停（优先级高于 Web）**、配网绑机。
- 技术要点：双通道（LAN 直连 agent / 云端中继）自动切换；LAN 模式视频直连 RTSP。
- 前提：P0 的 agent 本地直连服务稳定。

### P3 — 自主能力 R&D（并行线，不阻塞主线）

SDK 无 SLAM/导航，三条路线择一或组合：

| 路线 | 内容 | 代价 |
| --- | --- | --- |
| A. 外接 LiDAR 上装 | 狗背装雷达，上位机跑 SLAM + 导航栈 | 硬件改造，周期长 |
| B. 视觉里程计 | 利用前后深度相机做轻量定位 + 固定路线示教回放 | 精度有限，不动硬件 |
| C. 范围裁剪 | 产品定位"人工遥控巡检 + AI 识别"，自主导航列远期 | 零风险，影响卖点 |

产出后回填 Web 的路线地图/点位导航/一键返航、平板的"点地图走过去"。

### P4 — 运维与规模化

OTA 升级链路、远程日志、传感器标定工具（低层 DDS 的正当出口）、多机集群调度、断网缓存补传完善。

## 5. SDK 缺口与对策

| 缺口 | 影响的前端设计 | 对策 |
| --- | --- | --- |
| 无 SLAM/导航/全局定位 | 巡检路线地图、点位导航、一键返航 | P3 路线 A/B/C |
| 无热成像/云台/机械臂/雷达 | 红外通道、四宫格视频墙 | 删除或外接上装自研 |
| WiFi 下无 DDS（语音/精细遥测受限） | 喊话、电机温度、BMS | agent 部署在狗载上位机（决策 1） |
| Python 版仅有电量百分比 | 电池 SOH 仪表盘 | C++ 版取完整 BMS，或砍 SOH |
| 无重启/OTA/标定接口 | 设备页运维操作 | P4 自研运维通道 |
| 机体相对位姿 ≠ 全局定位 | 态势图位置标记、坐标 HUD | 标注"相对坐标"，全局定位随 P3 |

## 7. AI 巡检项（首期）

烟火识别、人员越界、垃圾满溢、表计读数、设备过温、气体异常（CO/H₂S 等，需上装传感器）、道路占用与积水。
